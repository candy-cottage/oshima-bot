## 六、冻结种子回归：做了什么，卡在哪（2026-11-14）

计划 §10 第 8 条要「固定种子的模拟/决斗/Boss/秘境回归稳定」。这一轮把它拆成两层，结果一层成、一层卡。

### 已成：规则层冻结样本

`OshimaBot.Tests/SeedScenario.cs` + `Fixtures/Seeded/regression.json`：22 条探针，
同种子逐值比对。覆盖抽卡（命中率 / 8 类产出 / 7 档品质 / 逐抽序列）、签到（天数阶梯 + 品质倾向）、
探索（5 档星级的分布与收益）、秘境（7 类 × 5 难度 × 单人/满编）、市场（手续费 + 两位小数展示口径）、
钻石兑换、分解返还、锻造（单一产地 / 混合产地 / 材料不足 / 产物抽取）、赛马、突破与升级三张消耗表、
运势哈希、商店日 4:00 切点，外加十连端到端（掷骰 → 入包 → 定价 → 橙色以上锁定）。

它的价值在于**断言具体值**：其余测试断言性质（区间、上限、等价样例），
概率表从 3.06% 改成 3.1%、返还从 8 改成 10、手续费口径带回 `Math.Max(1, …)`，性质测试全过、冻结样本当场报错。

防绕过的三道闸：

1. `digest`（`id\t值` 排序后 SHA-256）——手改数字而不重新生成，测试与 `check_claims.py` 都会拦；
2. 探针白名单（`SeededRegression_CoversEveryProbe`）——不能靠删探针让快照通过；
3. `SeededRegression_IsStableWithinProcess`——同进程跑两遍必须一致，
   谁在探针里混进 `Random.Shared` 或 `DateTime.Now`，这条先红。

重新生成（确认改动有意之后）：`OSHIMA_UPDATE_SEEDS=1 dotnet test --filter SeededRegression`。

### 卡住：整局模拟复现不了

`FunGameSimulation.SeedOverride` 有，注释也写着「同种子可复现整局」，但**实测不成立**：

| 试验 | 结果 |
|---|---|
| 同进程连跑 4 局（`SeedOverride=20261114`，混战） | 消息条数 44 / 59 / 54 / 49，摘要全不同 |
| 三个独立进程各跑 1 局 | 条数 43 / 50 / 56，摘要全不同 |
| 关掉周期空投（`EnablePeriodicDrop=false`） | 仍然不同（36 / 33 / 44） |
| 首个分歧位置 | 第 60 回合附近，局内决策层，不是收尾统计 |

**原因尚未证实**，目前只排除了三样：周期空投（关掉照样分岔）、天气（见下）、收尾统计
（分歧出现在第 60 回合，属局内决策）。唯一在查的方向是 `AIController`：它用 `Task.Run`
并行评估每个移动格、候选塞进 `ConcurrentBag`，虽然补了 tie-breaker（分数 → 行动类型 → 移动格 Id
→ 技能 Id → 物品 Id → 目标数），但没地图时大量格子 Id 相同，同分候选仍可能落回 bag 的枚举顺序。

> **更正（2026-11-15）**：本文件初稿写过「`Region.Weather` 用 `Random.Shared` 掷天气、天气参与伤害」，
> 这是错的。`Region.Weather` 只在内容初始化时掷一次，全仓除显示（`/地区列表`、地区详情）外
> **没有任何消费方**；内容里的 `GenerationPredicates`（`r => r.Weather == "永昼"`）从未被评估，
> 既不影响伤害也不影响刷怪。天气既不能解释模拟分岔，也不是任何数值的输入。

顺带查到的另一处 `Random.Shared`（与模拟无关，但影响**探索**的可复现性）：
`RegionUnit` / `RegionCharacter` 的构造函数用 `Random.Next` 掷 ATK/HP/MP/SPD/HR/MR，
即内容初始化时一次定死、每个进程不同——同一种子打同一地区的怪，属性会不一样。
要修得让内容构造接受可注入随机源（`OshimaRegions.CreateAll()` 与 `FunGameService` 静态初始化都要改），
本轮没动。

因此 `SimulationSeedReproducibilityTests` 里留了两条 `Skip` 用例（混战 + 团队）作为门禁草稿：
Core 修好后删掉 `Skip`，这两条就是「别再退化」的护栏。战斗整局暂时进不了冻结快照。
