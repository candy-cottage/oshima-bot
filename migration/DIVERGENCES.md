# 有意差异与范围排除决策表

> 迁移原则：**先等价，再修正**。任何不复制的旧行为都必须在这里登记，写明旧行为、新行为、影响范围与回归保护。
> 矩阵 `migration/matrix.tsv` 的「差异 / 备注」列以 `DIV-0xx` 引用本表；引用不存在的条目会被 `gen_matrix.py --check` 拒绝。
> 旧版按玩法定义的状态边界（Boss 战损写回、小队/共斗回血、探索 HP 快照、决斗满状态）属于产品取舍，不是旧版 bug。

## 有意差异（实现存在，但结果与旧版不同）

### DIV-001 Boss 讨伐的状态边界

- **旧版**：全服共享 10 只 Boss 池，Boss 有等级、动态强化与累计血量；玩家用库存角色挑战，战损写回角色，击杀后把剩余状态写回共享 Boss 池，因此第二次挑战可以接续削弱同一只 Boss。
- **新版**：每人每日一次抽象挑战，统一用满状态战斗副本，胜负按队伍评分与概率结算；Boss 等级（15/30/60）、击杀材料 = 等级、入场费 0 均保留。
- **影响**：Boss 不再是全服协作目标；「多人同时打 Boss 的写冲突」在新版不存在。
- **回归保护**：`FIX-BAT-BOSS`（`intentional-divergence`，申报差异字段 `sharedPool` / `poolSize`）；矩阵 BAT-005。

### DIV-002 锻造的费用与结算时长

- **旧版**：`GenerateForgeResult` 按提交材料所属地区的难度系数折算等效量，够数即出对应品质；不收费、无时长，提交即刻结算。
- **新版**：保留同一套地区系数、品质门槛与三段积分，额外收 200 金币并插入 1 分钟的「开始 → 收取」，与练级、探索共用同一会话交互。
- **影响**：单次锻造成本 +200 金币与 1 分钟；总产出概率不变。
- **回归保护**：`FIX-ITM-FORGE`（申报一致字段：材料门槛、地区系数、积分系数；差异字段：`costCredits` / `defaultMinutes` / `maxMinutes`）；矩阵 ITM-020、ITM-024。

### DIV-003 市场手续费取整、挂单上限与价格区间

- **旧版**：`fee = price * 0.15`，全程 `double` 不取整；不限每人挂单数；不限制价格。
- **新版**：费率同为 15%，但用整数除法且下限 1；每人最多同时挂 5 单；价格限制 1 ~ 1,000,000。
- **影响**：低价物品手续费偏高（15 金币售价旧版收 2.25，新版收 2）；大批量倒卖被 5 单上限约束。
- **回归保护**：`FIX-SHO-MARKET-SELL`（申报一致字段：`feeRatePercent`；差异字段：`fee` / `maxListings` / `minPrice` / `maxPrice`）；矩阵 SHO-026。
- **待办**：若认为下限 1 是错的方向，改为与旧版一致的浮点或四舍五入后再锁 fixture。

### DIV-004 小队讨伐 / 共斗的胜利回血

- **旧版**：胜利后自动回血或恢复，减少玩家反复使用生命之泉的时间成本。
- **新版**：没有持久 HP，无需回血；战斗结束即回到满状态。
- **影响**：原先的「回血」收益消失，但也不再有战损成本。
- **回归保护**：矩阵 PLY-026、BAT-006；`FIX-PLY-COOP` 待建。

### DIV-005 异步探索的战损快照

- **旧版**：探索使用角色副本，单独保存战后 HP 快照，结算时回写，用于隔离异步等待期间的并发修改。
- **新版**：不做战后 HP 快照，探索只结算经验、物品与任务进度。
- **影响**：探索不再产生需要恢复的战损。
- **回归保护**：矩阵 PLY-008 / PLY-009 / PLY-010；`FIX-PLY-EXPLORE` 待建。

### DIV-006 玩家决斗的状态边界

- **旧版**：战斗前 `Recovery(EP: 200)`，双方以最佳状态进入一次性配队对决，战后不保存 HP/MP/EP。
- **新版**：统一满状态战斗副本，与该模式的设计意图一致，差异只在没有 EP 概念。
- **回归保护**：矩阵 BAT-001；`FIX-BAT-PVP` 待建。

### DIV-007 房间重启清空

- **旧版**：房间是全局内存对象，进程重启即消失。
- **新版**：同样是进程内注册表，重启清空。
- **判定**：行为上等价，登记在此是因为它会影响「重启后玩家看到空列表」的预期，不能被误当成 bug 修。
- **回归保护**：矩阵 PLY-018 ~ PLY-023；`FIX-PLY-ROOM` 待建。

### DIV-008 懒建档与默认名

- **旧版**：必须先「创建存档」，否则所有命令提示未注册。
- **新版**：首次任意操作自动建档，默认名 `旅人` + 4 位随机字符（字符集去掉 `0/O/1/I`），不暴露内部 userId。
- **影响**：`/注册` 变成幂等操作；玩家不会因为没注册而卡在第一步。
- **回归保护**：`FIX-CHR-REGISTER`；矩阵 ARC-001。

### DIV-009 旧存档不导入

- **旧版**：MySQL 存档（已丢失）。
- **新版**：不提供迁移工具，所有玩家从空库开始。
- **回归保护**：无需；`/还原存档`（ARC-002）另行实现，见下条待办。

### DIV-010 改名走审核队列

- **旧版**：角色改名两步确认后立即生效；社团改名同样立即生效。
- **新版**：角色名与社团名都写入 `RenameRequests` 审核队列，管理员 `/批准改名` 后才生效；角色改名仅主战角色同步显示名。
- **影响**：改名从即时变为异步；这是平台合规要求，不是可选项。
- **回归保护**：矩阵 CHR-021、CLB-018；`FIX-CHR-RENAME-REVIEW`、`FIX-CLB-REVIEW` 待建。

### DIV-011 回复文本不逐字兼容

- **旧版**：各命令返回拼接好的纯文本。
- **新版**：统一 Markdown 四段式（标题 / 摘要 / 明细 / 下一步），字段语义一致但排版不同。
- **判定**：L3 展示等价不在交付范围；依赖旧文本的第三方脚本需另行提供兼容字段。
- **回归保护**：数值字段与错误条件由 fixture 覆盖；排版不做快照。

### DIV-012 抽卡物品的入包形态

- **旧版**：每抽到一件就把这个 `Item` 对象直接加进 `Inventory.Items`，同名的多件是彼此独立的实体；品质池为空时（例如内容包里没有「神话」品质的武器）`武器[Next(武器.Length)]` 会直接越界抛异常。
- **新版**：不锁定的物品按「同名 + 同品质 + 未锁定」并进已有堆叠（背包更像清单），橙品以上因为要锁定，按快照单独入库；品质池为空时回退到「同类型任意品质」，再空则回退到全部可抽物品。
- **影响**：数量与品质一致，差异在「背包里显示几行」和「不会因为内容包缺某个品质而崩」；这两条都是有意取舍，不回退到旧行为。
- **回归保护**：`FIX-ITM-GACHA`（品质阈值、8 类产出、重复角色折算、橙品锁定）；`GachaLegacyTests`（分布、重复折算、锁定）。

### DIV-013 库存搜索合并为一个入口

- **旧版**：两条入口——`库存搜索`（名称 **或** 描述包含关键词）与 `库存搜索2`（只比名称），都是区分大小写的 `string.Contains`。
- **新版**：只保留 `/库存搜索`，一律按「名称或描述包含」匹配，且**不区分大小写**（`OrdinalIgnoreCase`）。
- **影响**：`库存搜索2` 的结果在新版是 `库存搜索` 的子集，玩家用一条命令就能拿到更多结果；英文名大小写不再影响命中。旧命令 `库存搜索2` 由 `LegacyAliases` 重写过来。
- **回归保护**：`ItemFlowTests.Search_MatchesNameAndDescription`（名称命中、描述命中、无结果、大小写不敏感）。

### DIV-015 市场手续费在上架时预扣

- **旧版**：`MarketSellItem` 只把物品挂上去，不收费；买家成交时按 `fee = price × 0.15` 现扣，
  卖家收 `price − fee`。撤回挂单不产生任何费用。
- **新版**：上架时按同样费率预扣「上架费」（`fee = max(1, price × 15 / 100)`），成交时卖家收全额标价；
  **撤回挂单不退费**。
- **影响**：成交单的净额两种口径相同（都是 `price − fee`）；差别只在撤回与长期挂着不卖的单子——
  新版要付出一次上架费。另外费率取整沿用 DIV-003（整数除法、下限 1）。
- **回归保护**：`EconomyTests.Market_FeeIsChargedUpfrontAndNotRefundedOnDelist`、
  `Market_CompletedSaleNetsPriceMinusListingFee`（含账本 `market_fee` / `market_sale` 两笔）、
  `Market_EnforcesPriceBoundsAndListingCap`。

### DIV-014 旧存档的 Ex* 字段不能直接映射

- **2.1.1** 的存档里 `ExSTR` 表示「额外力量固定点数」，`ExSTR2` 是同名字段下的派生百分比值（不可写）。
- **v3** 把固定点数挪到了 `ExSTR2`，`ExSTR` 变成只读派生值（`ExSTR2 + ExSTR3`）。
- **影响**：把 2.1.1 的 JSON 存档直接喂给 v3，`ExSTR` 会被当成只读值丢弃、`ExSTR2` 会被读成「固定点数」——
  正是固定点数与百分比互换位置，数值会错。**本项目不导入旧 MySQL 存档**（数据已丢失），
  但将来若做「旧存档导入工具」，必须写字段级迁移，不能靠反序列化直通。
- **回归保护**：无（不导入旧存档）；此条用于阻止「顺手加个导入功能」时踩坑。

### DIV-016 秘境三处实现差异

- **货币与经验**：已按旧版口径实现——**每名出战角色各掷一次** `550–1049` 金币 / `3–6` 钻石 / `570–1259` 经验，
  再乘难度；4 人小队收益约为单人的 4 倍。旧版还会把战斗内击杀的金币（`GamingQueue.EarnedMoney`）计入总额，
  新版统一关闭回合奖励（`UseRoundRewards=false`），所以「战斗内掉落金币」这一块不复制。
- **掉落物品**：旧版「地区 / 突破 / 技能 / 魔法卡」四类秘境从**对应材料池按稀有度权重**抽取（权重随难度表变化）；
  新版统一产出一件「<类型>秘境掉落」并按掷出的品质决定档位，物品来源简化。
- **经验分配**：旧版把经验平均分给小队成员，溢出部分转成经验书；新版把全部经验记在主战角色身上（溢出继续升级）。

- **影响**：金币/钻石/经验的**量级与随人数、难度的缩放一致**；差别在掉落的品类与经验归属。
- **回归保护**：`EconomyTests.InstanceReward_ScalesWithMembersAndDifficulty`（1 人 vs 4 人、难度叠乘）、
  `Instance_RequiresExpiryThenDeliversRewards`（必须到点才能结算、结算给掉落与经验）。

### DIV-017 商店里的「虚拟商品」不复制

- **旧版**：商店货架上可以摆两种**虚拟商品**，买了不进背包、直接生效——买「钻石」直接 `Materials += count`，
  买「探索许可」直接把 `exploreTimes += count`（见 `FunGameService` 购买分支的两处 `SpecialItemID` 特判）。
  商店里显示它们只是为了展示，玩家拿不到这两个 Item 实体。
- **新版**：商店只卖真实物品（进背包）；钻石靠签到、重复角色折算、秘境获得，探索次数只有每日 60 + 两餐 +30。
  因此**没有「用金币买钻石 / 买探索许可」这条入口**。
- **影响**：配额与货币的产出路径少了一条（旧版可以用金币换钻石，等于给金币开了个出口）。
  若要补，应该在 `StoreCatalog` 里加「货币型商品」，按下单直接进钱包而不是背包。
- **回归保护**：`FIX-PLY-EXPLORE`（60 / +30 / 2 分钟 / 4 人 / 五档概率）、
  `ExploreServiceTests.Quota_StartsAtDailyBaseAndGrantsMealsOnce`（跨日重置与两餐只发一次）。

### DIV-018 社团任务 / 商店 / 市场：旧版只有帮助文本，没有实现

- **旧版**：`FunGameOrderList` 的社团帮助里列了 13 条命令（社团任务列表、做社团任务、社团任务结算、社团商店、
  社团商店查看/购买/出售、社团市场、社团市场出售/下架/查看/购买/清空），但
  `OshimaWebAPI` / `OshimaServers` / `OshimaModules` 里**只有帮助字典命中，没有任何实现代码**——
  属于「帮助写了、功能没做」。唯一留下的设计意图是那句帮助文案：
  「系统手续费 4%，社团收取 8% 作为社团基金」。
- **新版**：把这 13 条补齐成完整闭环——周常任务（捐献 5000 / 招募 3 / 征集 20，奖励 300/400/500 基金）、
  基金商店（钻石 260、四种印记 800–3200、时霜药剂 600）、社团市场（**社团基金 5%、系统不抽成**，每人 3 单、每社团 60 单）。
- **影响**：这些行在矩阵里的状态是 **`增强`**，不是「等价」——旧版没有可比的行为。
  费率与旧帮助文本的 4%+8% 不同是有意的简化：只收一笔、全部进社团基金，避免双重扣费；
  若将来要对齐旧文案，改成「系统 4% + 社团 8%」两笔即可，`ClubRules.MarketFee` 是单点。
- **回归保护**：`FIX-CLB-TASK` / `FIX-CLB-STORE` / `FIX-CLB-MARKET`（三者均为 `current-locked`，
  因为旧版无对照值）、`ClubServiceTests`（成员、审批、捐献、设置、解散、任务、商店、市场、改名审核）。

## 引擎公式对拍（2026-11-14）

旧版 NuGet 从 2.1.0 升到 **2.1.1**（tag `2.1.1` / commit `7ecb11f`「补齐核心属性百分比传导」），
并对照了本地源码 `../FunGame.Legacy/FunGame.Core` 与 v3 的 `FunGame/FunGame.Core`。

**两个 PR 别记混**（2026-11-14 查证）：

| PR | 仓库 | 内容 | 对数值的影响 |
|---|---|---|---|
| `#208` / `#207` | v2 / v3 | 补齐核心属性百分比加成到战斗属性的传导 —— 同一个修复的两侧 | 两边同步修，**互相等价** |
| `#210` | v3 | `refactor: 统一角色属性命名与额外值聚合`（`git log -S ExSTR3` 指向它） | 只改名与重新聚合，展开后数值不变 |

**逐条相同的部分**

| 项 | 2.1.1 | v3 |
|---|---|---|
| `BaseHP` | `InitialHP + (Level-1)(LevelToHPFactor + HPGrowthFactor·InitialHP) + BaseSTR·STRtoHPFactor` | 同 |
| `BaseMP` | 结构同上（MP 系数） | 同 |
| `BaseSTR/AGI/INT` | `Initial + Growth·(Level-1)` | 同 |
| `ATK` | `InitialATK + (Level-1)(LevelToATKFactor + ATKGrowthFactor·InitialATK)` | 同 |
| `OnLevelUp` | 扣 EXP、受突破进度约束、`OnAttributeChanged()` + `Recovery()` | 同 |
| 平衡常量 | 17 / 0.68 / 1.5 / 0.14 / 0.95 / 0.045 / 13 … | 同 |

**只是改名、数值等价的部分（PR#210）**

- 2.1.1：`ExSTR` = 固定点数（可写）、`ExSTR2` = `BaseSTR × ExSTRPercentage`（派生）、`STR = BaseSTR + ExSTR + ExSTR2`。
- v3：`ExSTR2` = 固定点数（可写）、`ExSTR3 = BaseSTR × ExSTRPercentage`、`ExSTR = ExSTR2 + ExSTR3`。
- HP 侧同理：2.1.1 `MaxHP = BaseHP + ExHP + ExHP2 + ExHP3`（`ExHP = (ExSTR+ExSTR2)·factor`）；
  v3 `MaxHP = BaseHP + ExHP`（`ExHP = ExHPFromExSTR + ExHP2 + ExHP3`）。**展开后完全一致。**

**由此确定**：升级/突破的属性派生值不需要「拿旧 DLL 采样」也能判定等价；真正需要注意的是**存档字段语义**（见 DIV-014）。
